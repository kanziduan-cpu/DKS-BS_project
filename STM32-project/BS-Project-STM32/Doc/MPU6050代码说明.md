# MPU6050代码说明

本文档对应工程：ESP8266蜂鸣器_LED灯_舵机。

当前工程里的 MPU6050 模块已经调整为纯串口输出版本，不再依赖 OLED。它的职责很单一：初始化 MPU6050，通过 I2C 周期性读取加速度、陀螺仪、温度数据，并通过调试串口打印出来。

## 1. 模块文件位置

MPU6050 相关代码主要分成两层：

1. 应用层
   - App/mpu6050/app_mpu6050.h
   - App/mpu6050/app_mpu6050.c
2. 驱动层
   - User/mpu6050/bsp_i2c_mpu6050.h
   - User/mpu6050/bsp_i2c_mpu6050.c

可以把它理解成：

1. 应用层负责“什么时候读、读完怎么处理、怎么打印”。
2. 驱动层负责“怎么通过 I2C 跟 MPU6050 通信”。

## 2. 当前硬件连接约定

当前综合工程采用的是最小改动方案：

1. MPU6050 使用 I2C1。
2. SCL 接 PB6。
3. SDA 接 PB7。
4. AD0 固定为 GND 或 3V3 对应电平。
5. ESP8266 保持原接法，占用 PB8、PB9、PB10、PB11。
6. INT 当前工程不使用，不接到 STM32。

推荐你按下面这张表直接接线：

| MPU6050模块引脚 | STM32F103C8T6引脚 | 说明 |
| --- | --- | --- |
| VCC | 3V3 | MPU6050 推荐 3.3V 供电 |
| GND | GND | 共地 |
| SCL | PB6 | I2C1_SCL |
| SDA | PB7 | I2C1_SDA |
| AD0 | GND | 推荐固定地址为 0x68 |
| INT | 不接 | 当前工程没有使用中断脚 |
| XDA | 不接 | 当前工程未使用辅助 I2C |
| XCL | 不接 | 当前工程未使用辅助 I2C |

这样做的原因是：

1. 原来 MPU6050 若继续占用 PB10/PB11，会和 ESP8266 的 USART3 冲突。
2. 改到 PB6/PB7 后，MPU6050 与 ESP8266 可以同时工作。
3. PB8、PB9 目前已经留给 ESP8266 的 IO 和 RST，不再给 MPU6050 使用。

## 3. 启动流程

主函数中的 MPU6050 相关启动顺序如下：

1. IIC_Init()
   - 初始化底层 I2C 外设。
2. MPU6050_Init()
   - 探测 MPU6050 地址。
   - 读取 WHO_AM_I 确认设备存在。
   - 写入关键配置寄存器，使传感器退出休眠并进入正常采样状态。
3. MPU6050_TaskInit(100)
   - 设置任务周期为 100ms。

也就是说，当前工程里 MPU6050 默认每 100ms 采样一次，能更及时地捕获摇晃和姿态变化。

## 4. 应用层说明

### 4.1 数据结构

app_mpu6050.h 中定义了任务结构体 MPU6050_TaskInfo，主要字段含义如下：

1. cycle
   - 任务执行周期，单位是 ms。
2. timer
   - 倒计时计数器，由 SysTick 中断递减。
3. flag
   - 到时执行标志，置 1 后主循环会调用 MPU6050_Handle()。
4. Accel[3]
   - 三轴加速度原始值。
5. Gyro[3]
   - 三轴陀螺仪原始值。
6. Temp
   - 转换后的摄氏温度。

### 4.2 函数说明

#### MPU6050_TaskReset()

作用：

1. 把 timer 恢复成 cycle。
2. 把 flag 清零。

用途：

1. 每次任务执行完后重新开始下一轮计时。

#### MPU6050_TaskInit(uint32_t mpu6050_task_cycle)

作用：

1. 保存任务周期。
2. 调用 MPU6050_TaskReset() 完成首次装载。

#### MPU6050_Task()

作用：

1. 检查 flag 是否置位。
2. 若到达执行周期，则调用 MPU6050_Handle()。
3. 任务处理完成后重新装载 timer。

这是一种典型的“中断置标志，主循环执行任务”的裸机调度方式。

#### MPU6050_Handle()

作用：

1. 读取三轴加速度。
2. 读取三轴角速度。
3. 读取原始温度值。
4. 将温度转换为摄氏度。
5. 计算姿态变化量和陀螺仪运动量。
6. 当姿态变化或角速度超过阈值时，触发本地蜂鸣器和 LED 报警。

当前工程里的本地报警不再只依赖“相邻两次姿态角差值”，还会同时参考陀螺仪峰值角速度，因此对剧烈摇晃更敏感。

## 5. SysTick 调度机制

MPU6050 任务不是在中断里直接读传感器，而是在 SysTick 中断里只做计时。

流程如下：

1. SysTick_Handler() 每 1ms 进入一次。
2. 如果 mpu6050_task.timer 大于 0，就递减。
3. 当 timer 递减到 0 时，将 mpu6050_task.flag 置 1。
4. 主循环中的 MPU6050_Task() 检测到 flag 后，才真正开始读传感器。

这样设计的好处是：

1. 中断里不做耗时 I2C 操作。
2. 主循环逻辑清晰，便于与 DHT11、MQ135、ESP8266、蜂鸣器、舵机等模块并行共存。

## 6. 驱动层说明

驱动层位于 bsp_i2c_mpu6050.c，负责与 MPU6050 寄存器交互。

### 6.1 关键宏

1. MPU6050_I2C_PORT
   - 当前定义为 IIC_I2C1，说明模块走的是 I2C1。
2. MPU6050_AD0D_SLAVER_ARRD
   - AD0 下拉时地址 0x68。
3. MPU6050_AD0U_SLAVER_ARRD
   - AD0 上拉时地址 0x69。
4. MPU6050_WHO_AM_I
   - WHO_AM_I 寄存器地址，用于识别设备。

### 6.2 地址探测逻辑

函数 MPU6050_SelectSlaveAddress() 会依次尝试两个地址：

1. 0x68
2. 0x69

判定成功的条件有两个：

1. IIC_CheckDevice() 能检测到该地址有设备应答。
2. 读取 WHO_AM_I 后，返回值等于 MPU6050_ID，也就是 0x68。

这样做的目的是兼容不同模块上 AD0 的接法，避免地址写死导致初始化失败。

### 6.3 寄存器访问函数

#### MPU6050_WriteReg(uint8_t write_addr, uint8_t byte)

功能：向指定寄存器写 1 个字节。

基本流程：

1. 发送起始信号。
2. 匹配从机地址。
3. 发送寄存器地址。
4. 发送寄存器数据。
5. 发送停止信号。

#### MPU6050_ReadReg(uint8_t read_addr)

功能：读取指定寄存器的 1 个字节。

基本流程：

1. 先以写模式发送寄存器地址。
2. 再次起始。
3. 切换为读模式。
4. 读取 1 个字节。
5. 发送停止信号。

#### MPU6050_ReadBuffer(uint8_t read_addr, uint8_t* buffer, uint32_t size)

功能：从指定寄存器开始连续读取多个字节。

典型用途：

1. 连续读取 6 字节加速度数据。
2. 连续读取 6 字节陀螺仪数据。
3. 连续读取 2 字节温度数据。

#### MPU6050_WriteBuffer(uint8_t write_addr, uint8_t* buffer, uint32_t size)

功能：从指定寄存器开始连续写入多个字节。

当前工程里主要用单字节配置，连续写接口更多是为了驱动完整性保留。

## 7. 初始化函数说明

### MPU6050_Init()

这是整个 MPU6050 模块最关键的入口函数。

它主要做了三件事：

1. 上电延时。
   - 给模块充足的稳定时间，避免刚上电就访问 I2C 导致失败。
2. 循环探测地址和设备 ID。
   - 如果没有检测到，会反复打印提示信息。
3. 写入初始化寄存器。
   - 解除休眠。
   - 设置采样分频。
   - 设置低通滤波。
   - 设置加速度量程。
   - 设置陀螺仪量程。

当前初始化参数的含义大致如下：

1. PWR_MGMT_1 = 0x00
   - 退出休眠。
2. SMPLRT_DIV = 0x07
   - 设置采样分频。
3. CONFIG = 0x06
   - 设置低通滤波参数。
4. ACCEL_CONFIG = 0x00
   - 加速度量程为 ±2g。
5. GYRO_CONFIG = 0x18
   - 陀螺仪量程为 ±2000 deg/s。

## 8. 数据读取函数说明

### MPU6050_ReadAcc(short *AccData)

从加速度寄存器起始地址连续读取 6 个字节，并拼成 X、Y、Z 三轴 16 位原始数据。

### MPU6050_ReadGyro(short *GyroData)

从陀螺仪寄存器起始地址连续读取 6 个字节，并拼成 X、Y、Z 三轴 16 位原始数据。

### MPU6050_ReadTemp(short *TempData)

读取温度原始寄存器值，返回原始整数数据。

### MPU6050_ReturnTemp(float *Temperature)

读取温度寄存器后，按下面公式转换为摄氏度：

$$
Temperature = \frac{RawTemp}{340.0} + 36.53
$$

这也是 MPU6050 数据手册中的常用温度换算公式。

## 9. 串口输出内容说明

当前运行时，MPU6050 模块会打印三类信息：

1. 初始化阶段
   - 是否检测到 MPU6050。
   - 当前识别到的 I2C 地址。
   - WHO_AM_I 读取值。
2. 周期采样阶段
   - 三轴加速度原始值。
   - 三轴陀螺仪原始值。
   - 原始温度值和换算后的摄氏温度。

因此，如果你只是先验证“模块是否在线、串口是否通、数据是否在刷新”，当前这版代码已经够用。

## 10. 常见问题排查

### 10.1 串口一直提示未检测到 MPU6050

优先检查下面几项：

1. 是否真的接到了 PB6 和 PB7，而不是之前的 PB10 和 PB11。
2. VCC 和 GND 是否正确。
3. AD0 是否悬空。
4. I2C 上拉是否正常，很多 MPU6050 模块板自带上拉。
5. 模块是否损坏。

### 10.2 能检测到设备，但数据异常

优先检查：

1. 电源是否稳定。
2. 线是否过长或接触不良。
3. 模块是否受到震动或固定不稳。
4. 是否误把原始值当成物理单位。

注意：当前打印的加速度和陀螺仪数据仍然是原始寄存器值，并不是换算后的 g 或 deg/s。

## 11. 当前代码定位总结

如果你后面还要继续改这个模块，可以按下面思路找位置：

1. 想改采样周期
   - 去 main.c 里改 MPU6050_TaskInit(1000) 的参数。
2. 想改串口打印格式
   - 去 app_mpu6050.c 里改 MPU6050_Handle()。
3. 想改初始化寄存器配置
   - 去 bsp_i2c_mpu6050.c 里改 MPU6050_Init()。
4. 想改底层通信方式
   - 去 bsp_i2c_mpu6050.c 和 i2c/bsp_i2c.c 看 I2C 读写流程。

## 12. 适合当前阶段的使用结论

你现在如果只是想先验证综合工程里其他模块是否可用，那么这版 MPU6050 代码已经足够：

1. 能判断模块是否在线。
2. 能输出基础传感器数据。
3. 不依赖 OLED，结构简单。
4. 不会占用 ESP8266 当前使用的 PB8 到 PB11。

后面如果你确认整机功能都正常，再决定要不要继续往下做：

1. 加速度和角速度物理量换算。
2. 姿态角解算。
3. 上传 MPU6050 数据到 ESP8266 云端。
4. 增加滤波或校准。
